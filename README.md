# saldo-test: веб-чат с ИИ

Одностраничный чат с языковой моделью через [OpenRouter](https://openrouter.ai).
Пользователь пишет сообщение — ответ модели появляется по мере генерации.
Тестовое задание на позицию frontend-разработчика.

## Быстрый старт (5 минут)

Требуется Node.js 20+.

```bash
npm ci
cp .env.example .env
# в .env подставить свой ключ: https://openrouter.ai/keys (достаточно бесплатного)
npm run dev
```

Открыть http://localhost:3000 — фронт на Vite, API проксируется на сервер (:8787).

Прод-режим (сервер сам раздаёт собранный фронт):

```bash
npm run build && npm start   # http://localhost:8787
```

## Ключевые решения

**Ключ не покидает сервер.** Браузер ходит только в `/api/chat`; ключ
подставляется на сервере из `.env`. Проверяется вкладкой Network: в запросах
со страницы ключа нет.

**Стриминг — SSE поверх fetch, а не EventSource.** EventSource умеет только GET
и не может отправить историю сообщений телом; fetch + `ReadableStream` даёт POST,
`AbortController` и честные HTTP-статусы ошибок.

**Отмена — AbortController на всём пути.** «Стоп»/Esc обрывает fetch на клиенте;
сервер слушает `res.on('close')` и обрывает запрос к OpenRouter, чтобы не жечь
токены. Частично полученный ответ остаётся в истории с пометкой «остановлено».

**Markdown в ответах — react-markdown + remark-gfm.** Модели постоянно отвечают
списками, кодом и таблицами; пузырь ассистента рендерит GFM (стили — ручной
набор `.md` на CSS-переменных, без typography-плагина). Сообщения пользователя
остаются plain text. Расплата — ~160 КБ бандла; для чата это оправдано.

**Тёмная тема — класс `.dark` на `<html>`, переключатель в шапке.** Палитра
через CSS-переменные (обе темы из коробки). Выбор хранится в localStorage —
это настройка интерфейса, а не диалог, поэтому наше решение «история умирает
с вкладкой» не нарушается. Дефолт — `prefers-color-scheme`.

**Reasoning показываем, но в историю не возвращаем.** Сервер запрашивает у
OpenRouter `reasoning: { enabled: true }` (иначе reasoning-модели «думают»
в полной тишине и стрим выглядит мёртвым) и форвардит дельты отдельным
SSE-событием; в UI они под спойлером. Но в последующие запросы рассуждения
не включаем осознанно: без tool calling API их просто игнорирует (DeepSeek),
OpenAI назад не принимает вовсе, а OpenRouter рекомендует возвращать только
при вызове инструментов — при этом reasoning-токены тарифицируются как output
и занимают контекстное окно. Рассуждение — процесс одного хода, а не память;
на каждый запрос модель рассуждает заново. Если появятся инструменты —
придётся сохранять и возвращать.

**Ошибки типизированы.** 429 (с `retryAfter`), таймаут, обрыв сети, нет/плохой
ключ — у каждого случая своё понятное состояние и кнопка «Повторить».
Нетипизированная ошибка (`unknown`) показывает спокойный текст, а технические
детали прячет под спойлер (`<details>` — нативно доступен с клавиатуры).

**Стейт — класс + `useSyncExternalStore`, без библиотек.** Весь стейт чата лежит
в `ChatStore` (наследник `Store` из `lib/store.ts`), экшены — обычные
async-методы, компоненты подписываются хуком `useStore`. Это тот же паттерн, что
внутри zustand, но без зависимости и с полным контролем: `getSnapshot` отдаёт
стабильную ссылку, обновления иммутабельные. Для MobX здесь слишком мало
состояния, а хуки с `useRef` для «свежих» значений быстро превращаются в цирк.

**История — в рамках сессии вкладки.** Перезагрузка страницы чат не переживает:
восстановленная после F5 история не приносит пользы, зато добавляет риски
(чужой диалог на общем устройстве, устаревшие состояния `error`/`stopped`).
Как прикрутить персистентность (localStorage), расписано в конце раздела
«Что бы я сделал дальше».

## Важные корнер-кейсы (обожглись вживую)

**Сигнал `fetch()` живёт весь запрос, а не до первого байта.** Первую версию
вачдога «модель молчит на старте» мы сделали через
`AbortSignal.timeout(FIRST_BYTE_TIMEOUT_MS)`, переданный в `fetch()`. В Node
этот сигнал остаётся привязан к запросу на всё время чтения тела — то есть
«таймаут первого байта» на деле был **тотальным лимитом на весь ответ**: ровно
через 60 с после старта он убивал стрим, даже когда токены активно текли
(воспроизводится стабильно: `TimeoutError` ровно на 60.000-й секунде посреди
ризонинга). Для reasoning-моделей, которые легко думают дольше минуты, это
гарантированный обрыв. Правильно: отдельный `AbortController` + `setTimeout`,
который отменяется сразу после получения заголовков; дальше работает только
idle-вачдог тишины, сбрасываемый на каждом чанке. Тотального лимита нет
осознанно — длинный ответ с живым потоком легитимен, подозрительна только
тишина.

**`req.on('close')` ≠ «клиент отключился» (дважды!).** В Node `req` эмитит
`close` сразу после того, как тело запроса полностью прочитано, — подписка на
него мгновенно обрывает апстрим. Слушать нужно `res.on('close')` с проверкой
`!res.writableEnded`. Мы наступили на это дважды: сначала в прокси, потом —
в тестовом моке OpenRouter, где та же подписка гасила интервал генерации
чанков до первого тика и мок «зависал» навсегда.

**Кнопка, превращающаяся в `type="submit"` посреди клика, сабмитит форму.**
Кнопки «стоп» и «отправить» в композере — один DOM-узел, который React
морфит на месте (тот же тег, та же позиция). Blink вычисляет activation
behavior клика *после* обработчиков: клик по «стоп» гасил генерацию, фаза
уходила в `idle`, узел синхронно перерисовывался как `type="submit"` — и тот
же клик дожимал форму, отправляя черновик (воспроизводится: печатаешь
черновик во время стрима, жмёшь «стоп» — черновик улетает). Лечится тем, что
кнопка отправки — `type="button"` с явным `onClick`: у него нет activation
behavior, фантомный клик — no-op, а Enter по-прежнему обрабатывает
`keydown` в textarea.

## Тесты

```bash
npm test            # оба набора
npm run test:server # интеграционные: настоящий прокси + мок OpenRouter
npm run test:logic  # логика ChatStore под Node
```

**Серверные** (`tests/server.test.mjs`, `node:test`, без внешней сети и ключа):
поднимаются мок OpenRouter и настоящий прокси, дальше сценарии по-настоящему
через HTTP/SSE — полный стрим, форвардинг reasoning, регрессия «стрим живёт
дольше first-byte таймаута», зависшие заголовки → 504, 429 с `retryAfter`,
обрыв сокета и ошибка посреди стрима (без `done` после ошибки), валидация
тела, отсутствие ключа, и дисконнект клиента, обрывающий апстрим (мок считает
открытые соединения в `/_stats`).

**Логика** (`src/testing/*.test.ts`): `ChatStore` гоняется на скриптованном
транспорте — сеть не нужна, всё детерминировано. Кейсы изоморфны: один и тот
же файл выполняется и в Node (через `tsx`), и в браузере. Свой крошечный
harness вместо vitest/jest: фреймворк не нужен для десятка кейсов, а так
тесты не привязаны к раннеру вообще.

**Интерактивный прогон в браузере**: кнопка «Тесты» в шапке (или `/#tests`)
открывает панель рядом с живым чатом — на десктопе она сжимает страницу
(оба видны одновременно), на мобиле открывается поверх, а во время прогона
сворачивается в полупрозрачную плашку сверху: текст контрольной точки и
«Далее». Каждый кейс можно запустить отдельно; в пошаговом режиме выполнение
встаёт на контрольных точках (`ctx.checkpoint`) до клика «Далее», в пакетном
— задерживается на них на 200 мс, чтобы смену состояний было видно глазами.
Сценарий при этом двигает настоящий видимый стор, так что каждый шаг
рендерится в чате. Это не дублированные «живые» тесты: те же самые кейсы,
контекст (`ctx.useTransport`/`ctx.checkpoint`) в Node — no-op и свежий стор,
в браузере — паузы и видимый синглтон. Запуск сбрасывает текущий диалог
(`reset()`); по окончании прогона настоящий транспорт возвращается, а
черновик в композере подчищается — сообщения остаются на экране для осмотра.
Закрытие панели посреди прогона доматывает его без пауз — чат не остаётся
подключённым к скриптованному транспорту в фоне.

### Консоль браузера

Стор всегда доступен как `window.store`:

```js
store.getSnapshot()      // текущий стейт: messages, phase, draft
store.send('Привет!')    // отправить сообщение
store.stop()             // остановить генерацию (Esc работает так же)
store.retry(messageId)   // повторить упавший ответ
store.setDraft('черновик') // набросок в композере
store.clear()            // очистить историю (только когда idle)
store.reset()            // полный сброс в любой момент, даже посреди стрима
```

## Осознанные отступления от буквы ТЗ

**Обводка фокуса.** ТЗ просит убрать дефолтный `outline`, потому что он выглядит
разнобойно. Полное удаление обводки ломает навигацию с клавиатуры (Tab-пользователь
не видит, где фокус) — а доступность в том же ТЗ требуется. Поэтому: дефолтный
`outline` убран (`focus-visible:outline-none`), вместо него единообразное
кастомное кольцо (`focus-visible:ring-2`). Требование выполнено по духу
(никакого разнобоя), а не только по букве.

**i18n не делаем.** Интерфейс целиком на русском, строки лежат прямо в
компонентах — это осознанно: для одностраничного тестового слой локализации —
лишняя сложность. Если понадобится, строки вынесутся в словарь `src/locales/`
и хук `t()` — точек с динамическим составлением строк мало.

## Что бы я сделал дальше

- Селектор модели в шапке: каталог с сервера (`/api/models`, метаданные
  OpenRouter — `context_length`, pricing) + прогревочная проверка доступности
  (`/api/models/check` — free-модели часто лежат или душат по rate-limit, и
  лучше знать это до отправки, а не в момент). На сервере при этом обязателен
  вайтлист суффикса `:free` — иначе через прокси можно жечь платные модели.
  Черновик этого лежит в ветке `feat/model-picker`.
- Индикатор длины контекста: занятое окно (оценка по токенам истории) против
  `context_length` выбранной модели — тонкий прогресс-бар в шапке, чтобы
  «модель внезапно глупеет» не было сюрпризом.
- Статистика по ходам: OpenRouter отдаёт `usage` (input/output/cached
  токены) в последнем чанке стрима — показывать под ответом ассистента,
  опционально цену (точную можно дотянуть из `/api/v1/generation?id=…`).
- BYOK: поле для своего ключа OpenRouter, чтобы гонять платные модели. Ключ
  живёт только в браузере (sessionStorage — до закрытия вкладки), прокси
  берёт его из заголовка запроса вместо `.env`, с явным дисклеймером в UI.
- Tool calls с interleaved thinking: типизированные блоки вызовов в пузыре,
  выполнение тула, возврат результата в историю. Тут важно: reasoning-модели
  требуют отдавать `reasoning_details` обратно в цепочке с тулколлами —
  наше решение «reasoning в историю не возвращаем» придётся точечно
  пересмотреть (хранить, но не рендерить).
- Для проверки bash и прочих тулов прямо в браузере — прикрутить
  [Lifo](https://lifo.sh/) (`@lifo-sh/core`, MIT): крошечная Linux-подобная
  ОС на чистом TypeScript, без WASM — шелл, coreutils, node и git в
  песочнице внутри вкладки. Модель дергает тул «bash», команда выполняется
  локально у пользователя, результат уходит в историю — полный цикл tool
  calling без единого бэкенд-процесса под выполнение.
- Мок OpenRouter для воспроизведения 429/таймаута/обрыва без сжигания
  free-лимитов — именно так проверялись все состояния ошибок.
- Тесты на `chat-api` (vitest + msw).
- Сноски в markdown сейчас сломаны. remark-gfm их парсит (`[^1]` → sup-ссылка
  + `section.footnotes`), но наша обёртка ссылок (`target="_blank"`) заставляет
  якоря сносок открывать новую вкладку, блок сносок не стилизован, а прыжок по
  `#user-content-fn-…` конфликтует с hash-роутингом (`#tests`). Править:
  исключить `data-footnote-ref`/`data-footnote-backref` из обёртки и добавить
  стили `.md` для `sup` и `.footnotes`.
- Тест-панель тоже сделать стором (`TestPanelStore`: running/paused/results)
  и гонять её тем же изоморфным harness — сейчас её стейт-машина живёт в
  React-компоненте и покрыта только ручной проверкой.
- Тонкий e2e-слой на headless Chromium: DOM-уровневые баги (вроде кнопки
  «стоп», сабмитящей форму) изоморфные тесты стора не ловят принципиально.
  Репродукционные скрипты уже написаны — превратить их в тесты несложно.

### Как прикрутить персистентность (история между перезагрузками)

Осознанно не делали (см. «История — в рамках сессии вкладки»), но задел под
это уже есть: весь стейт — один сериализуемый снапшот в `ChatStore`. Схема:

1. **Сохранение**: подписка `store.subscribe` → debounce ~300 мс →
   `localStorage.setItem('saldo-chat', JSON.stringify(store.getSnapshot()))`.
   Дебаунс важен: во время стрима снапшот меняется на каждый чанк, писать
   синхронно — значит дёргать сериализацию и диск на каждый токен.
2. **Восстановление**: в конструкторе `ChatStore` читаем ключ, парсим и
   **валидируем форму** (версия снапшота + проверка полей — иначе старый
   формат после обновления кода уронит приложение). Статусы воскрешаем
   аккуратно: `streaming` → `stopped` (стрим перезагрузку не переживает,
   `AbortController` не сериализуется), фазу `awaiting`/`streaming` → `idle`.
   Черновик восстанавливаем как есть.
3. **Очистка**: `clear()` и `reset()` дополнительно делают
   `localStorage.removeItem` — иначе стёртая история воскреснет после F5.
4. **Живой тест**: как только тест-панель станет стором (пункт выше), её
   состояние сохраняется тем же механизмом — и сценарий «checkpoint →
   перезагрузка → история и черновик на месте, фаза idle» можно прогонять
   прямо из панели, а не руками.

## ИИ-лог

Проект написан в паре с ИИ-агентом (Kimi, Moonshot AI): он писал код, гонял
тесты, проверял живое поведение в headless-браузере, оформлял ветки и PR.
Я ревьюил каждый PR и тыкал интерфейс руками — большинство багов ниже нашёл
именно я, а не агент. Честно, как того и просит ТЗ.

**Поймано мной при ревью и ручном тестировании:**

- **Стрим умирал ровно на 60-й секунде ризонинга.** Заметил в серверном логе
  `TimeoutError` ровно на 60.000 с и спросил, сбрасывается ли таймаут на
  чанках. Оказалось хуже: `AbortSignal.timeout()` живёт весь запрос —
  «вачдог первого байта» был тотальным лимитом (подробно — в «Важных
  корнер-кейсах»). Для reasoning-моделей это гарантированный обрыв.
- **Кнопка «Стоп» отправляла черновик.** При непустом композере клик по
  «стоп» гасил генерацию и тут же отправлял набранный текст. Причина —
  activation behavior в Blink плюс морфинг кнопки React'ом (тоже в
  «Важных корнер-кейсах»). Агент воспроизвёл с инструментовкой `send()`
  в headless-браузере и починил.
- **Черновик оставался в композере после прогона тестов.** `reset()` между
  кейсами чистил мусор в начале *следующего* теста, но после *последнего*
  его никто не звал.
- **Панель «дожимала» замороженный тест при открытии, а не закрытии.**
  Заметил по странному таймингу: тест сбрасывался в момент открытия панели.
  Резюм запаркованного чекпоинта стоял не на той ветке эффекта, и пока панель
  была закрыта, чат оставался на скриптованном транспорте.
- **Перезапуск упавшего теста не зеленел.** Я нажал настоящий «Стоп» посреди
  теста guards (закономерно его уронил) — а повторный запуск вис. Утёкший
  ран в `finally` безусловно затирал контроллер и фазу следующего рана.
  Починено гардом владения + регрессионным тестом, который мутационно
  проверен: на старом коде падает.

**Поймано агентом самим (для симметрии):** гонка двух чекпоинтов в панели
(тест и его транспорт ждали разные точки, баннеры перезатирались) — всплыла
при его же живой проверке перед пушем; путаница `req`/`res.on('close')` в
